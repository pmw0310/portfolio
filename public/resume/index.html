간략 소개

IoT 에너지 모니터링 플랫폼에서 웹과 모바일을 6년 이상 설계하고 운영한 프론트엔드 시니어입니다.

레티그리드에서 AngularJS 레거시를 Next.js로 전환하는 하이브리드 아키텍처를 설계했습니다. 전면 교체가 거부된 상황에서 iframe 기반 병행 구조를 제안하여 서비스 중단 없이 핵심 기능의 50% 이상을 마이그레이션했습니다. 빌드 도구도 gulp에서 webpack을 거쳐 Vite로 전환했는데, AngularJS를 지원하지 않는 Vite 환경에서 호환성 문제를 해결하여 적용한 경험이 있습니다.

대규모 센서 데이터 환경에서 API 병렬 처리와 SWR 캐싱 전략을 적용해 조회 성능을 개선했고, ECharts 다운샘플링으로 대용량 차트 렌더링을 안정화했습니다.

Flutter 기반 iOS/Android 앱을 기획부터 스토어 배포까지 전담하면서 Figma를 조직에 도입하여 UX 기획 프로세스를 체계화했습니다.

팀장으로서 스프린트 기반 개발 프로세스를 수립하고, 프론트엔드 아키텍처 의사결정을 총괄했습니다. 한 제품을 처음부터 끝까지 책임져온 경험을 바탕으로 프론트엔드 아키텍처 설계와 기술 리딩에 기여하겠습니다.

자 기 소 개 서

1. 지원동기

6년 넘게 같은 제품을 만들었습니다. EnergyWatch라는 IoT 에너지 모니터링 플랫폼이었고, 입사 첫날 AngularJS로 돌아가는 코드를 읽는 것부터 시작했습니다.

AngularJS 지원이 끊기면서 Next.js 전환을 제안했는데, 전면 교체안은 리스크가 크다는 이유로 거부당했습니다. 대신 iframe으로 두 프레임워크를 병행하는 구조를 설계했고, 서비스를 멈추지 않으면서 핵심 화면의 절반 이상을 옮겼습니다. 빌드 도구도 gulp에서 webpack, 다시 Vite로 바꿨는데, Vite가 AngularJS를 지원하지 않아서 호환성 문제를 하나하나 잡아가며 적용했습니다. 웹이 어느 정도 안정되자 모바일 앱도 맡게 되었고, Flutter로 화면 설계부터 스토어 배포까지 진행했습니다.

아키텍처 설계, 번들러 전환, 성능 최적화, 팀 리딩까지 경험했지만, 한 제품 안에서만 반복된 판단이라는 한계가 있었습니다. 더 많은 사용자를 대상으로 더 다양한 기술 문제를 풀 수 있는 환경에서 프론트엔드 시니어로 일하고 싶습니다.

2. 직무역량

프론트엔드 개발자로서 가장 자신 있는 부분은 레거시 환경에서 실용적인 해법을 찾아 실행까지 끌고 가는 것입니다.

AngularJS에서 Next.js로 전환할 때 전면 교체는 불가능했습니다. 운영 중인 서비스를 멈출 수 없었고, 일정도 빠듯했습니다. iframe으로 두 프레임워크를 병행하는 하이브리드 구조를 설계하고, 신규 기능부터 Next.js로 개발하면서 기존 화면은 변경이 많은 것 위주로 순차 전환했습니다.

빌드 도구도 gulp에서 webpack을 거쳐 Vite로 바꿨습니다. Vite는 AngularJS 전용 플러그인 자체가 없어서 적용 사례를 찾기 어려웠습니다. templateUrl로 HTML을 참조하는 AngularJS 구조가 Vite에서 동작하지 않아 ?raw 쿼리로 텍스트를 불러와 컴포넌트에 삽입하는 방식으로 우회했고, ng-click이나 이중 중괄호 같은 AngularJS 문법이 빌드 중에 비표준으로 인식되어 제거되는 문제는 빌드 설정을 조정해 보존 처리했습니다. CommonJS를 ESM으로 전환하는 작업과 esbuild 축소 시 의존성 주입이 깨지지 않도록 설정하는 것도 함께 해결했습니다.

성능도 풀어야 했습니다. 센서 200개 이상이 설치된 환경에서 장기간 데이터 조회 시 타임아웃이 발생했는데, 요청을 분할하여 병렬 처리하고 부분 실패만 UI에 표시하는 예외 처리를 넣었습니다. 한 제품의 웹부터 모바일까지 전부 만져본 것이 저의 핵심 역량입니다.

3. 역경극복

레티그리드에 입사했을 때 프론트엔드 개발자는 저 포함 소수 인원이었고, 대부분의 기간 동안 아키텍처 의사결정을 직접 이끌었습니다.

기술 판단의 근거를 스스로 만들어야 하는 환경이었습니다. AngularJS 전환 방향을 정할 때도, Vite를 AngularJS에 적용할 때도 직접 검증하고 결정했습니다. 특히 Vite 적용은 AngularJS용 플러그인이 존재하지 않았고, 인터넷에서도 사례를 찾기 어려워서 정보 수집부터 난관이었습니다.

그래서 방법을 바꿨습니다. 모든 기술 의사결정을 dev 서버에서 먼저 검증하고, 문제가 없을 때만 production에 반영하는 원칙을 세웠습니다. Vite 적용도 HTML 템플릿 로딩, AngularJS 문법 보존, CommonJS 전환, DI 호환성 문제를 하나씩 격리해서 해결했습니다. Next.js 전환도 한꺼번에 하지 않고, 신규 기능부터 시작해서 단계적으로 진행했습니다.

AngularJS 전면 전환을 제안했다가 거부당한 적이 있었습니다. 그때 iframe 하이브리드라는 차선책을 찾아낸 것이 오히려 서비스 안정성을 지키면서 전환을 완료할 수 있었던 이유였습니다. 스스로 판단해야 하는 환경에서 문제를 작게 쪼개고 하나씩 검증하는 습관이 자연스럽게 자리잡았습니다.

4. 향후 포부

지금까지는 한 제품 안에서 필요한 것을 만들어왔습니다. 아키텍처 설계가 필요하면 설계했고, 모바일 앱이 필요하면 Flutter를 배워서 만들었고, 디자인이 필요하면 Figma를 잡았습니다.

앞으로는 범위를 넓히고 싶습니다. 먼저 더 큰 규모의 서비스에서 프론트엔드 아키텍처를 설계하고 싶습니다. 대규모 트래픽 환경에서 SSR 전략이나 번들 최적화, 성능 모니터링 체계를 깊이 있게 다뤄보고 싶습니다.

아울러 최근 실무에 도입하고 있는 Antigravity와 RAG 등 AI 엔지니어링 역량을 프로덕트에 적극 접목하고자 합니다. 단순한 도구 활용을 넘어, 도메인 특화 지식 검색과 지능형 워크플로우를 웹 서비스에 유기적으로 결합하여 사용자 경험을 혁신하고 개발 생산성을 극대화하는 현대적 엔지니어링 환경을 구축하고 싶습니다.

규모 있는 프론트엔드 조직에서 동료들과 코드 리뷰와 컨벤션을 함께 고도화하며 기술적으로 상호 성장하고, 한 제품을 끝까지 책임져본 오너십과 AI 역량을 결합하여 귀사의 비즈니스 성장에 확실한 기술적 추진력을 더하는 시니어가 되겠습니다.

5. 성격의 장/단점

장점은 코드에 대한 책임감입니다. 레티그리드에서 6년 이상 프론트엔드를 주도적으로 맡다 보니, 제가 작성한 코드가 곧 서비스의 안정성으로 직결되는 환경이었습니다. 자연스럽게 다음에 이 코드를 읽을 사람이 빠르게 이해할 수 있는지, 예외 상황에서 깨지지 않는지를 확인하는 습관이 생겼습니다. AngularJS에서 Next.js로 전환하는 동안에도 기존 서비스가 정상 동작하는 것을 최우선으로 두었고, 전환 기간 중 서비스 장애 없이 운영을 유지했습니다.

단점은 한 가지 작업에 깊이 빠지면 주변 요청에 대한 반응이 늦어지는 편입니다. 복잡한 기술 문제를 풀 때 몰입하다 보면 동시에 들어오는 다른 업무를 놓치는 경우가 있었습니다. 그래서 업무를 시작하기 전에 총괄 이사가 정리해준 요구사항 목록을 보고 우선순위를 먼저 정하는 방식으로 일하고 있습니다. 가장 중요한 작업부터 순서대로 처리하면 몰입과 전체 일정 관리를 함께 할 수 있었습니다.
